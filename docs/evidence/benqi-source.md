# BENQI source admission — pinned fork evidence

Observed 2026-09-11. `npm run test:source` runs three executable tests against Avalanche mainnet block **95031281**. Proxy `0x2b2C81e08f1Af8835a78Bb2A90AE924ACE0eA4bE`; implementation `0xB791C7A42FD0D10F90DEaa906a8735f79719FA53`. Exact implementation bytecode hash and explorer source bundle digest are in benqi-pin.json (`npx tsx scripts/probe-benqi.ts`). Published explorer verified source uses Solidity 0.6.12, GPL-3.0. EXIT uses a newly written interface/account; it does not copy that implementation.

Executed: deposit one fork AVAX via a bounded account, request its minted shares, confirm requests belong to the account and not the EOA, transfer ownership, reject former-owner cancellation/withdrawal, cancel and return sAVAX to the current owner; miss the window and recover overdue shares to the current owner; redeem the entire request and withdraw native AVAX to current owner. **3 tests passed**. No partial redemption claim.

Cooldown is 1,296,000 seconds (15 days), redemption window 172,800 seconds (2 days). Requests denominate shares; proceeds use source exchange-rate history. Exact return is not guaranteed. Early cancellation/overdue recovery returns shares; ordinary cash zero does not terminate ownership.

Material source drift discovered: handoff's old `accrueRewards(uint256)` selector reverts on current implementation. Current explorer ABI is `accrueRewards()` payable, rejects zero value, and handles a protocol reward share. Test was corrected using the actual ABI. The successful redemption test advances **fork time only** and impersonates the actual rate publisher to submit one wei of rewards at the future cooldown boundary. This simulates an otherwise unavailable future operator transaction; it does not change source storage or force source liquidity. Other tests need no operator simulation. No live protocol timing is accelerated.

Trust: upgradeable proxy; role administrators can grant/revoke operator privileges; operators may pause, adjust timing/caps/reward share, withdraw delegation liquidity, and publish rewards. Admission cannot eliminate these risks. Source's whole-request semantics and swap-and-pop indexing favor one originated request per bounded account. No arbitrary execution, delegatecall or token approval surface exists on the prototype. EOA-originated requests cannot be imported by approving sAVAX.

**Boundary:** `packages/source/BenqiClaimAccount.sol` is a source-admission prototype, not admitted to the TestWithdrawalVault settlement market or the frontend. No BENQI Fuji deployment or live BENQI trade is claimed. Full financial integration would require a dedicated source settlement adapter and independent review; the pinned fork validates the proposed caller-owned acquisition/recovery mechanism required by the handoff.
